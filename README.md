# Проверка RAG-поиска без LLM

Учебный пример XNova: десять искусственных фрагментов документации, шесть запросов с заранее размеченными релевантными документами и детерминированный поиск по совпадающим словам.

## Требования

Python 3.12 или новее. Поиск и расчёт метрик работают без сторонних библиотек, сети, векторной базы, LLM и API-ключей. Для тестов нужен `pytest`.

## Проверка

Из корня репозитория:

```bash
python -I run_checks.py
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Первая команда выводит найденные `doc_id`, Precision@3, Recall@3, обратный ранг первого релевантного документа и макросредние по пяти положительным запросам. Шестой запрос без релевантных документов проверяется на пустую выдачу отдельно. Последняя команда запускает 17 тестов, включая ручной эталон метрик, устойчивый порядок результатов и регрессию после перестановки.

## Как устроен пример

`documents.json` содержит текст и уникальные `doc_id`. `qrels.json` хранит идентификаторы запросов, формулировки, полный для этого корпуса набор релевантных документов и обоснования ручной разметки. `retriever.py` использует Unicode-токены, `casefold` и количество совпадающих уникальных слов; при равенстве оценок сортирует по `doc_id`. `metrics.py` рассчитывает P@3, Recall@3 и RR@3.

Для простого лексического поиска запрос «как вернуть деньги» не находит фрагмент «Возврат средств». Это намеренно сохранённое ограничение алгоритма; изменение эталонной релевантности под его результат исказило бы проверку.

Внимание: маленький искусственный корпус не позволяет оценить качество семантического поиска на реальных пользовательских данных и не проверяет генерацию ответов.
